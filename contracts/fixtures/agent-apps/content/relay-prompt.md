# Review a Relay reply draft

Use the installed opl-relay owner to reuse an authorized mailbox.read/draft.create
connection. relay_connections discovers readiness; relay_connection_request is
only the missing-access repair route. UI arguments cannot activate a consumer.
Read the selected storage_ref, create or inspect the original reply request, then
read the exact account_id, draft_id and revision through relay_draft.

Read the task's bound correspondence policy. Use owner-collaboration to open that
same draft in the dedicated workbench and let the person edit it. Save through
relay_save with the exact revision, body and attachment_ids, then read relay_draft
again. A saved draft is the terminal review artifact; it is never a sent message.
If the creation outcome is unknown inspect the original request_id; if a save is
stale refresh the owner draft before another decision. Without UI, obtain the
edit as text and use the same conditional owner save. Credentials and private
knowledge stay with their sources and do not enter generated package content.
