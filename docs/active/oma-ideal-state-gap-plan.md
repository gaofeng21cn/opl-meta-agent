# OMA Open Acceptance Work

This page owns unresolved acceptance evidence. It does not define architecture,
repeat repository status, prescribe future tasks, or confer permission to run,
activate, release, or adopt an Agent.

The source declares the public/provider boundary in
[`action_catalog.json`](../../contracts/action_catalog.json) and
[`foundry_provider.json`](../../contracts/foundry_provider.json). The design and
improve fixture suites exercise protocol objects, lineage, and non-weakening
semantics. Their conformance is separate from a real model producing and
transporting a candidate through Foundry.

| Unclosed evidence | Owner | Closure condition |
| --- | --- | --- |
| Current OMA design and diagnosis through Foundry | OPL Foundry | A current invocation returns the correct protocol object and every referenced content artifact; immutable review snapshots bind those bytes and the applicable provider-operation scope |
| Candidate evaluation and lifecycle acceptance | OPL Foundry and target owner | Exact candidate, independent evaluation, qualification, and applicable canary, activation, rollback, and owner receipts for the requested target |
| Published and installed Package currentness | Package publication and carrier owners | Readbacks bind the requested source to the actual published and installed versions; repository manifests or a configured publication ref alone do not close this item |

The current Framework adapter passes operation-scoped output requirements and
requires protocol and referenced content bytes in the immutable reviewer
snapshot. That implementation is not a live-model acceptance result. A repository
test pass cannot close any row above without the row's own evidence.

Remove a row when its evidence is available and place the receipt with its
execution or publication owner. New work belongs here only after a current
contract, consumer, or readback identifies a concrete unmet requirement.
